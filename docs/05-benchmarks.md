# 05. 実測値

個人環境での実測です。条件を併記します。

## 環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11 Pro |
| 生成 | ComfyUI（Docker / ai-dock base） |
| 映像合成 | Remotion 4.x |
| LLM | llama.cpp b11368 |
| 計測 | 2026年10月〜11月 |

### マシン

| 項目 | M1 | M2 |
|---|---|---|
| CPU | Threadripper 2990WX (32C/64T) | Threadripper 1920X (12C/24T) |
| GPU | RTX 3060 12GB | RTX 3080 10GB |
| RAM | 64GB | 64GB |
| 用途 | 画像・動画・LoRA・レンダ | 高速画像・動画・リップシンク |

## 画像生成（SDXL）

| マシン | 1枚あたり | 条件 |
|---|---|---|
| M2（RTX 3080） | **約4秒** | SDXL / 1024px / 20 steps |
| M1（RTX 3060） | 約12秒 | 同上 |

VRAM 10GBのM2が速いのは、単純にメモリ帯域と演算性能の差です。
M1はVRAM 12GBを活かしてLoRA訓練と長尺動画を担当します。

## 動画生成

| マシン | クリップ | 条件 |
|---|---|---|
| M2 | **約5秒** | Wan 2.2 TI2V 5B / 832×480 / 16f |
| M1 | 約10秒 | 同モデル |

### VRAMの内訳（M2 / Wan 2.1系）

| 解像度 | フレーム | VRAM |
|---|---|---|
| 512×288 | 49f | 2.9GB |
| 640×368 | 81f | 6.4GB |
| 832×480 | 81f | 8.2GB |
| 832×480 | 160f（約10秒） | 8.3GB |

CLIP（umt5_xxl fp8）が約6.3GBを占めるため、
`--lowvram --force-fp16` が必須でした。

## LoRA訓練

| 項目 | 値 |
|---|---|
| 手法 | kohya_ss / SDXL |
| 速度 | 2.40 s/it |
| マシン | RTX 3060 12GB |
| バッチ | M2では `batch_size=1` に低減 |

## ローカルLLM

| 指標 | M1 | M2 |
|---|---|---|
| モデル | 125B MoE (UD-Q2_K_XL) | 同左 |
| コンテキスト | 256K | 128K |
| KV量子化 | Q8_0 | Q4_0 |
| 生成速度 | 10.8〜11.0 t/s | 11.2〜11.7 t/s |
| プリフィル | 110〜120 t/s | 175〜184 t/s |
| VRAM | 11.6 / 12.0 GB | 9.3 / 10.2 GB |

### KV量子化の比較

| K | V | 4K文脈 | Flash Attention |
|---|---|---|---|
| q8_0 | q8_0 | **10.84 t/s** | 有効 |
| q4_0 | q4_0 | 約10 t/s | 有効 |
| q8_0 | q4_0 | **0.70 t/s** | **無効** |

混在指定はエラーも警告も出ません。速度だけが落ちます。

## レンダリング

| 構成 | 実測 | 備考 |
|---|---|---|
| 2台（M1 + M2） | 15.7分 | 長尺1本（約19.6分） |
| 3台 | 11.2〜12.7分 | フレーム分割 |
| 結合誤差 | 0.07秒 | 期待1,174.33 / 実測1,174.40 |
| 継ぎ目16フレーム | MD5一致 | マシン間 |

GPUラスタライズ（`--gl=angle-egl`）とNVENCも試しましたが、
GPU使用率が10%未満でソフトウェアと差が出ませんでした。
ボトルネックはフレーム生成とI/Oで、CPUコア数と並列度が効きます。

## スループットの目安

| 処理 | 1時間あたり |
|---|---|
| 画像生成（M2） | 約900枚 |
| 動画クリップ（M2） | 約720本（832×480 / 16f） |
| LLM生成（M1） | 約38,000トークン |

試行回数をコストから切り離せているため、
**品質を上げるために生成を増やす**という判断ができます。

## 測定方法と注意

- 生成速度はウォールクロック（モデルロード済み・ウォームアップ後）
- LLMは `completion_tokens / 経過秒`
- プリフィルはサーバーログの `prompt eval time`
- レンダは同期・転送を含む
- モデル・量子化・解像度が変われば数値は変わります
